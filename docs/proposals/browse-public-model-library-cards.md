# 提案：浏览公共模型库与公开模型卡片

## 动机 / 用户故事

普通用户可以进入公共模型库，浏览所有已经审核通过且未下架的模型。本提案只负责公共列表和模型卡片，不包含搜索、筛选、详情、下载或收藏。

## 目标用户

- 浏览公开模型的普通用户
- 未登录的访客（如产品允许公开访问）

## 现有做法及不足

无。当前没有公共模型库或模型卡片。

## 本期范围

本期做：

- 公共模型库列表页，展示所有审核通过且未下架的模型卡片
- 模型卡片展示：封面、标题、作者、分类、发布时间、收藏数、下载数
- 默认按 `(published_at, model_id)` 倒序形成稳定唯一顺序（审核通过时间，非创建时间）
- 使用游标分批加载：首次加载固定数量，响应返回绑定当前条件的 `nextCursor`
- 加载下一批时不重复、不遗漏，到达末尾后明确表示没有更多
- 页面状态覆盖：加载中、空状态、加载失败（含重试）、单张封面失败（占位图）
- 禁看规则在数据返回阶段执行，不依赖前端隐藏
- 模型审核通过后刷新可见，下架后刷新消失
- 新模型版本不自动替换已审核的公开版本

本期明确不做：

- 不做关键词搜索和分类筛选
- 不做推荐算法和复杂排序
- 不做模型详情页和 3D 预览
- 不做收藏和我的收藏
- 不做 STL / 3MF 下载
- 不做举报和 Fork
- 不做评论、关注或排行榜

## 关键决策与依据

### 备选方案

1. 前端过滤
   - 优点：实现简单
   - 缺点：私有/未审核模型数据暴露给前端
2. 数据层过滤
   - 优点：安全性好，非公开模型不出现在响应中
   - 缺点：需要后端明确过滤逻辑

### 本期选择

选择方案 2（数据层过滤）。原因：非公开模型不得以任何形式暴露，即使前端隐藏卡片也存在安全风险。

### 分页方式

交互可使用分页按钮或“加载更多”，数据契约统一使用 `(published_at, model_id)` 游标；不得使用会因列表变化产生重复或遗漏的 offset 作为跨批次边界。

## 基本概念与信息结构

### 模型卡片

- `model_id`: 模型标识，用作稳定排序的第二关键字
- `published_version_id`: 当前审核通过的公开版本；所有卡片字段均从该不可变版本读取
- `cover`: 封面图
- `title`: 模型标题
- `author`: 作者
- `category`: 分类
- `published_at`: 公开时间（审核通过时间）
- `favorites_count`: 收藏数
- `downloads_count`: 下载数

### 分页游标

- `nextCursor`: 编码最后一项的 `published_at`、`model_id` 及当前查询条件。
- 下一批只返回严格排在该边界之后的项目；新审核通过的模型不会插入当前游标之后，也不会造成已返回项目重复。

### 公开状态规则

可展示：状态为"已公开"且当前未被下架

不可展示：
- 私有模型
- 审核中的模型
- 审核未通过的模型
- 已下架模型
- 上传或生成失败的模型

## 原型 / 演示

### 演示流程

```
准备：
模型 A：已公开
模型 B：审核中
模型 C：审核未通过
模型 D：已下架

用户进入公共模型库
-> 只看到模型 A
-> 看不到模型 B、C、D

管理员审核通过模型 B
-> 用户刷新公共模型库
-> 模型 B 出现在列表最前面

管理员下架模型 A
-> 用户刷新公共模型库
-> 模型 A 从列表消失
```

## 验收标准

### 例子 1：正常浏览

- 现状：无公共模型库。
- 提议后的行为：用户进入公共模型库，看到审核通过且未下架的模型卡片列表，按公开时间倒序排列。
- 验收：API 响应只包含状态为"已公开"且未下架的模型；每张卡片包含 `model_id`、`published_version_id`，封面、标题、作者、分类、发布时间、收藏数和下载数均来自该审核通过版本。

### 例子 2：分批加载

- 现状：无。
- 提议后的行为：首次加载固定数量模型，用户点击加载更多后追加下一批，不重复不遗漏。
- 验收：使用第一页返回的 `nextCursor` 请求第二批，两批之间无重复项；多条模型具有相同 `published_at` 时仍按 `model_id` 稳定排序；到达末尾后明确提示"没有更多"。

### 例子 3：空状态

- 现状：无。
- 提议后的行为：当前没有任何公开模型时，页面显示明确的空状态说明。
- 验收：页面不展示空列表或空白区域，而是显示"目前没有公开模型"等提示。

### 例子 4：加载失败

- 现状：无。
- 提议后的行为：列表加载失败时显示错误信息和重试入口。
- 验收：点击重试后重新请求列表；单个封面加载失败显示占位图，其他卡片正常展示。

### 例子 5：非公开模型不可见

- 现状：无。
- 提议后的行为：无论是否登录，任何人都不能通过公共模型库看到非公开模型。
- 验收：API 响应的模型列表不包含私有、审核中、审核未通过、已下架或生成失败的模型。

### 例子 6：版本控制

- 现状：无。
- 提议后的行为：已公开模型产生新版本时，公共列表继续展示经过审核的版本，不自动切换到未经审核的新版本。
- 验收：作者上传新版本后，公共列表中的卡片信息仍指向已审核版本。

### 例子 7：未登录访问

- 现状：无。
- 提议后的行为：若产品允许未登录访问，访客可以查看公共列表；若不允许，访客被引导登录。无论哪种方式，非公开模型不可见。
- 验收：未登录时访问公共模型库的行为符合产品登录策略；API 响应始终不包含非公开模型。

### 例子 8：翻页期间列表发生变化

- 现状：第一页返回后若有新模型审核通过，offset 分页可能重复或跳过原有项目。
- 提议后的行为：后续请求沿用第一页的稳定游标边界，不受边界之前新增模型影响。
- 验收：读取第一页后新增一条公开时间更晚的模型，再使用原 `nextCursor` 读取第二页；原列表项目无重复、无遗漏，新模型仅在重新开始第一页查询时出现。
