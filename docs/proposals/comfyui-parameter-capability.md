# 提案：ComfyUI Parameter Capability

## 动机 / 用户故事

外部 Agent 需要根据用户需求调整 Hunyuan3D 多视图生成参数。ComfyUI 参数分散在不同节点中，不适合作为外部长期协议，因此需要建立统一的 Parameter Capability，将内部节点参数转换为稳定、可查询、可修改和可审计的业务参数。

## 目标用户

- 调用 ComfyUI 生成能力的外部 Agent
- 需要查询参数定义和覆盖参数值的开发者
- 需要审计参数变更的运维人员

## 现有做法及不足

参数分散在各个 ComfyUI 节点中，没有统一的参数描述、校验和审计机制。调用方需要硬编码参数含义和目标节点，每次节点升级都可能破坏兼容性。

## 本期范围

本期做：

- Parameter Schema 定义和发布：为每个可调用的生成能力发布对应的 Parameter Schema
- 参数名称、说明、类型和默认值
- 参数范围、枚举和格式约束
- 参数覆盖与合并规则：按照默认配置、预设配置和调用方覆盖进行解析
- 最终生效参数解析：形成 resolved parameters，在生成任务提交时冻结
- 参数权限和风险分级：普通、高级、运行和管理参数
- 资源成本描述
- 参数变更审计
- 参数版本和兼容性管理：相同 Schema Version 下参数语义保持稳定

本期明确不做：

- 全参数开放不包含任意节点连线和原始 graph 开放
- 不允许调用方控制服务器绝对路径
- 不允许未知参数被静默忽略
- 不允许无权限调用方修改受限参数
- 已提交生成任务的参数不可原地修改
- 参数 Schema 只描述对外业务语义，不暴露内部实现细节

## 关键决策与依据

### 备选方案

1. 直接暴露 ComfyUI 节点参数
   - 优点：零实现成本
   - 缺点：参数随节点变化，无稳定契约
2. 建立 Parameter Capability 抽象层
   - 优点：稳定对外协议，内部节点变化不破坏调用方
   - 缺点：需要维护 Schema 定义和转换逻辑

### 本期选择

选择方案 2。原因：长期来看，稳定的参数协议是外部 Agent 集成的前提；内部节点升级不应影响调用方。

## 基本概念与信息结构

### Parameter Schema

- `name`: 参数业务名称
- `description`: 参数用途
- `type`: 数据类型
- `default`: 默认值
- `range` / `enum`: 可选范围或枚举值
- `required`: 是否必填
- `permission_level`: 权限等级
- `risk_level`: 风险分级
- `resource_impact`: 资源与质量影响
- `version`: 版本信息

### Resolved Parameters

从默认配置、预设配置和调用方覆盖合并后形成的最终生效参数，在生成任务提交时冻结并作为任务记录保存。

## 验收标准

### 例子 1：查询参数定义

- 现状：参数定义分散在节点中，无可查询接口。
- 提议后的行为：调用方可以查询某个生成能力的完整 Parameter Schema，获取所有参数的名称、类型、默认值、约束和说明。
- 验收：Schema 中每个参数有唯一字段名、明确类型、默认值、约束和说明文档。

### 例子 2：参数覆盖

- 现状：需要直接修改 ComfyUI workflow 来调整参数。
- 提议后的行为：有权限的调用方可以通过参数覆盖接口修改允许覆盖的参数值。
- 验收：覆盖请求中指定的参数值反映在 resolved parameters 中；未覆盖的参数保持默认值。

### 例子 3：未知参数拒绝

- 现状：未知参数可能被忽略，调用方不清楚是否生效。
- 提议后的行为：覆盖请求中包含 Schema 未定义的参数时，请求被拒绝并明确告知哪些参数无效。
- 验收：包含未知参数的覆盖请求返回参数校验失败错误，列出无效参数名。

### 例子 4：参数冲突检测

- 现状：无。
- 提议后的行为：参数之间存在约束冲突时（如互斥配置），在生成任务创建前被发现并拒绝。
- 验收：提交互斥参数组合时，任务创建失败并返回冲突说明。

### 例子 5：权限控制

- 现状：无权限分级。
- 提议后的行为：受限参数（如管理级参数）只能被有相应权限的调用方修改。
- 验收：无权限调用方尝试修改受限参数时请求被拒绝。

### 例子 6：参数快照保存

- 现状：无。
- 提议后的行为：每个生成任务保存完整的 resolved parameters 快照。
- 验收：任务记录中包含完整的生效参数，可用于审计和复现。

### 例子 7：版本兼容

- 现状：无版本管理。
- 提议后的行为：相同 Schema Version 下参数语义保持稳定；不兼容变更伴随版本号升级。
- 验收：同一版本下参数名称、类型和语义不发生变化；升级版本有变更说明。
